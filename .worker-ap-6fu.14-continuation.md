## Bounded hypothesis and implementation

The exact Codex source resolver merges configured provider definitions into built-ins, lets an active root profile replace route fields, and accepts project/runtime layers outside the one file supplied to the installer. A root `model_provider = "openai"` therefore does not by itself prove the built-in OpenAI provider or the installed effective model route.

Target-only guards now fail closed in `pkg/adapters/codex/install.go`:

- Root `profile`, `profiles`, dotted profile keys, and `[profiles.*]` reject because active profile selection or profile definitions can shadow root route fields.
- Opaque root `model_providers = { ... }` rejects because the inline map cannot be classified without a complete TOML semantic parser.
- `[model_providers.openai]`, quoted `[model_providers."openai"]`, and dotted `model_providers.openai.*` reject as unambiguous built-in provider shadowing.
- Root `openai_base_url` rejects because it can rebind the built-in provider endpoint.
- Unrelated `[model_providers.other]` state remains byte-preserved and installable in the target-only characterization path.
- The adapter emits `codex.install.precedence_bounded`: only the explicitly supplied config document is changed. Project-local layers and runtime overrides are not inspected or controlled. No runtime enforcement or authentication identity is inferred from provider ID.

Production Codex metadata remains `Installable: false`, `StatusBlocked`, and records the source-native field-consumption milestone while keeping installed-binary equivalence, project/runtime precedence, active-profile selection, and OAuth identity blocked. The registry was not edited.
